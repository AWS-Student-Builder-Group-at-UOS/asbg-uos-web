# 발표 썸네일 생성 프롬프트

아래 전체를 복사해 AI에게 전달한다. 맨 위 "입력"의 경로만 고쳐 쓴다. 파일을 첨부하는 환경이면 경로 대신 파일을 첨부한다.

---

## 입력

- 디자인 가이드: `template/presentation-thumbnail/design-guide.html`
- 발표 폴더: `cohort-01/activities/session-01-presentation-01`
- 유형: `index.md`의 `type: presentation`, `session`, `presentation`을 확인한다.
- 발표 자료: `cohort-01/activities/session-01-presentation-01/index.md`, `cohort-01/activities/session-01-presentation-01/files/slides.pdf`

## 작업

너는 ASBG UOS 웹사이트의 발표 썸네일을 만든다. 위 디자인 가이드를 기준으로 삼고, 위 발표 자료를 읽어 발표를 대표하는 아이콘을 직접 그린 뒤 SVG 썸네일 한 장을 만든다.

가이드는 HTML 원문으로 읽는다. 렌더링 없이도 필요한 내용이 모두 들어 있다. 템플릿 원문은 `<script id="template">`, 세션 번호 숫자는 `<script id="digits">`, 예시 아이콘의 격자 데이터는 `<script id="glyphs">`에 있다. 치수 · 색 · 문자 규칙은 02 ~ 04절, 세션 번호는 05절, 아이콘 그리기 규칙은 06절, 검증 항목은 08절, 템플릿과 생성 명령은 09절이다.

## 절차

1. 발표 자료를 끝까지 읽고 아래 "아이콘 고르기"대로 사물 후보를 2 ~ 3개 정한다.
2. 후보마다 가이드 6.3 규칙대로 16 × 16 격자 문자열을 새로 그린다. 예시 아이콘은 그리는 방식만 참고하고 그대로 가져오지 않는다.
3. 후보마다 썸네일을 만들어 아래 "다듬기"대로 비교하고 하나를 고른다. 고른 격자도 "다듬기"의 기준을 모두 통과할 때까지 고친다.
4. `index.md`의 frontmatter에 `thumbnail: img/thumbnail.svg`가 있는지 확인하고, 없으면 추가한다.
5. 고른 격자 16줄만 담은 텍스트 파일을 임시로 저장하고 저장소 루트에서 아래 명령을 실행한다. 기수 · 발표 번호, 키워드, 세션 숫자는 스크립트가 폴더 이름과 `index.md`에서 채우고 08절 검증까지 한다.

   ```bash
   node template/presentation-thumbnail/build.mjs <발표 폴더> <아이콘 격자.txt>
   ```

6. 저장소를 실행할 수 없는 환경이면 가이드 09절 템플릿을 그대로 복사해 다섯 자리(`{{COHORT}}` `{{PRESENTATION}}` `{{KEYWORDS}}` `{{ICON}}` `{{DIGITS}}`)를 채우고 08절 검증 항목을 직접 확인한다.
7. 임시 격자 파일과 비교용 렌더링 파일을 지운다.

## 아이콘 고르기

- 먼저 이 발표가 청중에게 남기려는 말을 한 문장으로 적는다. 제목, `description`, 본문의 결론, 발표 자료의 마지막 장을 본다. 키워드 세 개만 보고 고르지 않는다.
- 그 문장을 사물 하나로 바꾼다. 발표가 직접 다루는 기기나 서비스가 있으면 그것을 그리고, 개념이면 그 개념을 떠올리게 하는 물건으로 바꾼다. 1기의 예: 함께 배우는 이유 → 모여 선 사람들, 스타트업의 빠른 시도 → 로켓, 클라우드 진로 → 이정표, AI 시대의 전략 → 로봇, 네트워크 → 공유기, 3-Tier → 3단 서버.
- 처음 보는 사람이 카드 크기에서 1초 안에 한 단어로 이름을 댈 수 있는 사물이어야 한다. IT 아이콘 세트나 일상에서 흔히 보는 모양이 좋다.
- 어느 발표에나 붙일 수 있는 범용 기호는 피한다. 톱니, 전구, 별, 체크 표시, 문서, 말풍선이 그렇다. 발표가 바로 그 사물을 다룰 때만 쓴다.
- 개념을 도식으로 그리지 않는다. 노드와 선으로 된 구성도, 층을 쌓은 막대, 화살표 흐름은 작게 줄이면 다른 것으로 읽힌다. X(닫기), 가로줄 세 개(메뉴), 더하기처럼 UI 기호로 읽히는 모양도 피한다.
- 같은 기수의 다른 발표 아이콘과 겹치지 않게 한다. 이미 쓴 아이콘은 각 발표 폴더의 `img/thumbnail.svg`에서 확인한다.
- 확인 질문: "제목을 가리고 아이콘만 본 사람은 무엇이라고 부를까? 그 이름을 들은 청중은 이 발표를 떠올릴까?" 둘 다 그렇다면 통과다. 하나라도 아니면 다른 사물을 고른다.

## 다듬기

- 후보 썸네일을 활동 카드 크기(폭 약 360px, 아이콘 폭 약 80px)와 그 절반 크기로 렌더링해, 같은 세션의 다른 썸네일과 나란히 놓고 비교한다. 렌더링할 수 없는 환경이면 격자 문자열을 멀리서 보듯 실루엣만 보고 판단한다.
- 실루엣만으로 사물이 읽혀야 한다. 특징을 하나 지워도 같은 사물로 읽히면 그 특징은 빼서 단순하게 만든다.
- 같은 세션의 아이콘과 크기 · 무게가 비슷해야 한다. 혼자 작거나 혼자 꽉 찬 덩어리로 보이면 고친다.
- 가이드 6.3 규칙(면 실루엣과 특징, 긴 쪽 12 ~ 14칸, 가운데 배치, 대칭, 45° 계단, 흩어진 점 없음)을 하나씩 확인한다.

## 규칙

- 색은 `#0B0F17` `#42B4FF` `#FFFFFF` 세 가지만 쓴다. 아이콘과 세션 숫자는 `#42B4FF` 단색, 불투명도 1이다.
- 문자는 템플릿의 여섯 줄만 쓴다. 발표 제목 · 발표자 · 한글을 넣지 않는다.
- 키워드는 `index.md` 값을 그대로 쓴다. 바꾸거나 줄이지 않는다. 29자 이상인 키워드가 있으면 썸네일을 만들기 전에 `index.md`의 키워드부터 줄인다.
- 세션 번호는 가이드 05절의 숫자 모양을 그대로 쓴다.
- 글꼴 · 이미지 · 필터 · 그라디언트를 더하지 않는다.
- 아이콘은 하나다. 글자 · 숫자 · 타사 로고 모양을 아이콘으로 쓰지 않는다.

## 출력

- 발표 폴더의 `img/thumbnail.svg`로 저장한다. 파일에는 SVG 코드만 넣는다.
- 마지막에 발표를 요약한 한 문장과 고른 사물, 선택 이유를 보고하고, 아이콘 격자 문자열 16줄을 함께 남긴다. 비교한 다른 후보는 탈락 이유를 한 줄씩 적는다.
