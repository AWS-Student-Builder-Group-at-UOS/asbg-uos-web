## 이런 세션이었습니다

9월 29일 화요일 저녁 정보기술관에서 진행한 2차 세션은 온라인 쇼핑몰 하나를 키워가는 시리즈의 첫 회차였습니다. 목표는 하나였습니다. 브라우저 주소창에 주소를 치는 순간부터 EC2 인스턴스가 응답을 돌려주기까지, 요청 하나의 여정을 참가자 스스로 그림으로 설명할 수 있게 되는 것입니다. 이후 회차에서 쇼핑몰이 커지더라도 이 그림이 바탕이 되기 때문에, 서비스 이름을 많이 외우는 것보다 네트워크의 경계가 어디서 갈리는지를 정확히 이해하는 데 시간을 썼습니다.

진행은 황수진(Tech Lead)이 맡았습니다. 앞 55분은 VPC, 서브넷, 보안 그룹을 순서대로 짚고, 각 개념이 끝날 때마다 데모 계정의 콘솔 화면을 열어 실제 설정 항목이 어디에 있는지 확인했습니다. 화이트보드에는 처음부터 큰 사각형(VPC, 10.0.0.0/16) 하나를 그려두고, 설명이 진행될수록 그 안에 서브넷과 인스턴스를 채워 넣었습니다. 그 다음 15분은 라이브 데모로 t3.micro 인스턴스를 하나 띄웠고, 마지막에 요청의 여정을 화이트보드에 함께 그리며 90분을 마쳤습니다. 남은 30분은 1차 과제(루트 MFA, Budgets) 제출 확인과 개별 질문에 썼습니다.

가장 많이 헷갈린 지점은 예상대로 퍼블릭 서브넷과 프라이빗 서브넷의 구분이었습니다. 서브넷 생성 화면에 "퍼블릭"이라는 선택지가 없다는 걸 확인하고 나서야, 라우팅 테이블에 인터넷 게이트웨이로 가는 경로가 있는지가 유일한 기준이라는 설명이 와닿았습니다. 보안 그룹의 아웃바운드 규칙을 따로 만들지 않아도 응답이 나가는 이유(상태 저장)도 질문이 이어진 부분입니다.

## 함께 짚은 개념

- **VPC** — AWS 계정 안에 논리적으로 격리된 가상 네트워크입니다. CIDR 블록(예: 10.0.0.0/16)으로 쓸 수 있는 IP 대역을 정하는 것이 첫 결정입니다.
- **서브넷** — VPC를 더 작게 쪼갠 네트워크로, 하나의 가용 영역에 속합니다. 가용 영역 자체는 "한 곳이 죽으면?"이라는 질문을 남겨두고 이번에는 개념만 짚었습니다.
- **퍼블릭 vs 프라이빗** — 서브넷 자체의 속성이 아니라, 연결된 라우팅 테이블에 0.0.0.0/0 → 인터넷 게이트웨이 경로가 있는지로 갈립니다.
- **인터넷 게이트웨이** — VPC와 인터넷 사이의 출입구입니다. 만들기만 하면 끝이 아니라 VPC에 연결하고 라우팅 테이블에 경로를 추가해야 동작합니다.
- **보안 그룹** — 인스턴스 단위 방화벽입니다. 기본은 전체 차단이고 허용 규칙만 추가하는 화이트리스트 방식이며, 상태 저장이라 인바운드로 들어온 요청의 응답은 아웃바운드 규칙 없이도 나갑니다. NACL은 이번에 다루지 않았습니다.
- **EC2** — 인스턴스를 만들 때 고를 것은 AMI(운영체제 이미지), 인스턴스 타입(사양), 스토리지, 키페어(SSH 접속 키) 네 가지로 정리했습니다.

## 과제와 결과

과제는 선택이었습니다. VPC 1개와 퍼블릭 서브넷 1개를 만들고 EC2 인스턴스 1대에 Apache나 Nginx를 설치해, 본인 브라우저에서 퍼블릭 IP로 접속한 웹 페이지 스크린샷을 올리면 완료입니다. 예상 소요 시간은 1~1.5시간으로 안내했습니다. 비용은 프리티어 범위인 t2.micro 또는 t3.micro만 쓰고, 실습이 끝나면 인스턴스를 Stop 또는 Terminate하도록 슬라이드 마지막 장에 넣었습니다. 심화로는 프라이빗 서브넷을 하나 더 만들어 두는 것을 제안했습니다.

제출된 결과에서 반복된 막힘은 두 가지였습니다. 첫째, 보안 그룹에 SSH용 22번만 열고 80번을 빠뜨려 SSH 접속은 되는데 브라우저는 계속 로딩만 되는 경우입니다. 둘째, VPC를 "VPC만" 옵션으로 만든 뒤 라우팅 테이블에 0.0.0.0/0 경로를 추가하지 않아, 인스턴스에 퍼블릭 IP가 있어도 밖에서 닿지 않는 경우입니다. 둘 다 세션에서 화면으로 확인한 지점이었는데, 직접 하다 보면 다시 놓치게 된다는 점을 확인했습니다.

## 세션에서 나온 질문

**Q.** Route 53은 오늘 실습에 없는데 요청의 여정에는 왜 들어가 있나요?
A. 사람이 기억하는 건 도메인이고 네트워크가 아는 건 IP라서, 실제 서비스라면 브라우저가 먼저 DNS에 IP를 물어보는 단계가 앞에 붙습니다. 이번 과제는 퍼블릭 IP를 직접 입력하기 때문에 이 단계를 건너뛰는 것이고, 그림에는 전체 흐름을 남겨두기 위해 넣었습니다.

**Q.** 보안 그룹에 인바운드 80만 열었는데, 응답이 브라우저로 나가는 건 아웃바운드 규칙을 따로 안 넣어도 되나요?
A. 됩니다. 보안 그룹은 상태 저장이라 허용된 인바운드 요청에 대한 응답은 자동으로 나갑니다. 기본 아웃바운드 규칙이 전체 허용이기도 해서 실습 중에는 아웃바운드를 건드릴 일이 거의 없습니다.

**Q.** 실습이 끝나고 Stop만 하면 요금이 전혀 안 나오나요?
A. 인스턴스 사용 요금은 멈추지만 연결된 스토리지 요금은 소액이나마 계속 나옵니다. 프리티어 범위 안이면 문제되지 않지만, 다시 안 쓸 거면 Terminate가 깔끔합니다. Stop 후 다시 시작하면 퍼블릭 IP가 바뀐다는 점도 함께 짚었습니다.
